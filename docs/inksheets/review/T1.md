## Findings

### Data loss / parts that vanish

**T1-01 · S1 · A file renamed only in letter case makes its song disappear for good.**
Renamed `Colonial Song.pdf` to `colonial song.pdf` (Explorer, or Syncthing delivering a case change from another OS) -> next scan reports `removed=[Colonial Song: MobileSheets/Colonial Song.pdf]`, the song is gone from Home, and every later scan leaves it gone while the file sits in the folder (the "removed stays removed" rule `removedAt >= file.modified` skips it because a rename keeps the date). Expected: follow the file like any other move. Cause: `LibraryScan` compares `part.file !in onDisk` case-sensitively, but treats `unclaimed` case-insensitively, so the new name is never offered as the moved file, and the old one is "watched go".
Evidence: `T1Core2Test.r3 a case-only rename of a file` ("case-only rename: ... removed=[Colonial Song ...] song listed=false"). Same logic on Android/Fedora where the file system is case-sensitive and Syncthing may deliver exactly this.
Status: open.

**T1-02 · S2 · A file deleted, then put back with its original modified date, is never re-added.**
Deleted `Chester.pdf` (scan removed the song), copied it back keeping its old date (what an Explorer copy or a restore from backup does) -> `added=[]`, song stays gone until the file is touched. Expected: it comes back (or at least the log says why it was ignored). Cause: `removedAt >= file.modified -> continue` in step 3 of `LibraryScan.run`. This guards "deletion not yet arrived from another device" but cannot tell a person's own re-copy.
Evidence: `T1Core2Test.r3 a file deleted then copied back keeps its old date`.
Status: open.

**T1-03 · S2 · Song editor Save writes a stale snapshot of the parts: a part that arrived meanwhile is deleted and stays hidden.**
Opened a song's Details (snapshot of parts), a new `Blinding Lights - Tuba.pdf` arrived by the folder scan (now 3 parts), pressed Save -> song has 2 parts, tuba file still on disk, rescan does not bring it back (same "stays removed" rule as T1-02). Expected: Save writes only what the person changed (diff against the snapshot), as `readUnknownParts` already does by re-reading the song at write time. `SongEditorDialog` does `this.parts = parts.toList()` -> `Library.setParts` deletes every current part not in the list.
Evidence: `T1Core2Test.r3 song editor save is a stale snapshot`.
Status: open.

## Ideas from Slate's Home

InkSheets' library management is clumsier than Slate's new Home (`library-ui`: LibraryHome, DragToFolder, FolderPicker, RecentlyDeleted) in these ways, each a thing it could adopt:

1. **Undo and Recently deleted for everything.** Slate keeps deleted documents and folders 30 days with a short Undo at the time. InkSheets has a Trash for songs only, with no Undo, and nothing for setlists, folders, or a replaced part (T1-24, T1-25, T1-06). Adopt: a snackbar "Removed Chester - Undo" on every remove/delete; extend the trash to setlists/folders (a deleted-flag already exists; only the list in Settings is missing); put "Recently deleted" in the Home menu rather than five scrolls down in Settings.
2. **Move to... at any depth.** Slate's FolderPicker walks folders like a file manager, opens where the thing already is and offers recent targets. InkSheets moves setlists/folders only by hold-drag onto a visible folder or breadcrumb step: to put a set three folders deep you go folder by folder, and there is no menu route for phones/touchpads. Adopt: "Move to..." in the setlist and folder menus with the same picker (and recent targets: Games / Concerts).
3. **Drag with a dock.** Slate shows a strip of folders at the bottom while carrying, so a folder scrolled off or inside another is reachable, and resting on one opens it. InkSheets has no autoscroll or dock while dragging.
4. **Drag songs onto a setlist.** Songs can only be added through "Add to setlist..." (a chooser dialog per song). With Slate's drag, hold a song and drop it on a setlist or on the set open beside it (split view on laptop).
5. **Select several.** Slate selects many documents and moves/deletes them together. InkSheets acts on one song, one setlist at a time: merging 6 duplicate songs, trashing a bad import, or adding 10 songs to a set is 10 round trips. Adopt: long-press a song to enter selection; actions Add to setlist / Merge into... / Remove.
6. **Right-click and two-finger click menus at the pointer; Enter confirms.** Right-click on a song row opens nothing (checked), the kebab is at the far right of a 1600 px row, and Enter does not confirm New folder, Save as setlist, Rename (checked for the first two).
7. **Sort into class folders = sort scans into songs.** Slate's "Sort into class folders" suggests moves from names and lets you accept them in one go. InkSheets' equivalent: a review list for the leftovers ("17", "30", "6 35 PM Wed Sep 30", no-instrument parts) - "This looks like Trombone 1 of Chester: Accept all / Review".

## What would make it genuinely useful (ideas)

- A **Recently added** strip at the top of Home right after a Syncthing arrival or import ("3 new: ..."), so nothing arrives unseen.
- **One find** for songs, setlists and bookmarks together; "trombone 2" finds songs having a Trombone 2 part, and tapping a result with a part opens that part.
- A **"Needs attention" row** that replaces "No tempo (29)" / "No instrument (13)" / "File missing (n)" / held-back removals: one tappable line, hidden when empty.
- Save-as-setlist from the open tabs already exists: keep the tab order and default the name.
- A bundle share that asks **"All parts / only my parts / only the parts for people I choose"** and writes to a temp folder, not into the synced library.
